1. Introducción

Un conjunto es un grupo de elementos donde no hay repetidos y no importa el orden. Aunque la idea viene de las matemáticas, en informática se usa para organizar, comparar y combinar datos.

Esta aplicación de consola, hecha en Java, trabaja con conjuntos de números enteros o textos. Se guardan de dos formas, en un vector y en una lista ligada, construidas sin usar las colecciones de Java. Los datos permanecen en memoria mientras el programa está abierto.

2. Importancia de los conjuntos en la informática

Muchas tareas del día a día se apoyan en conjuntos, aunque no se vean. Un registro que no acepta dos veces el mismo correo está evitando repetidos. Un buscador que muestra lo que coincide con dos palabras hace una intersección, y un sistema que revisa si un usuario tiene los permisos necesarios comprueba un subconjunto.

Las bases de datos también ofrecen operaciones de unión, intersección y diferencia para combinar o descartar información. Por eso entender los conjuntos ayuda a expresar mejor un problema y a elegir una estructura adecuada para resolverlo.

Los conjuntos no dependen de los menús ni de la lectura. Por eso se puede cambiar la forma de pedir los datos sin tocar las operaciones. Los atributos son privados y solo se modifican por medio de los métodos de cada clase.

Los dos menús se parecen porque cada uno trabaja con su propio tipo de conjunto. Una interfaz común evitaría repetir código, pero se prefirió conservar las firmas de la guía y mantener el programa sencillo.

4. Representación en vector

La clase tiene dos atributos: n, que es la capacidad, y vec, el arreglo de elementos. Estos van seguidos desde la posición cero y el primer null marca el final.

n = 5

posición     0      1      2      3      4
vec       [ 10 ] [ 20 ] [ 30 ] [null] [null]     cantidad = 3

No es lo mismo cuánto cabe que cuánto hay: getN devuelve la capacidad y cantidadDeElementos cuenta las posiciones ocupadas. Al borrar, los elementos que siguen se corren a la izquierda para no dejar huecos:

Antes de borrar el 20     [ 10 ] [ 20 ] [ 30 ] [null] [null]
Después                   [ 10 ] [ 30 ] [null] [null] [null]

5. Representación en lista ligada

Aquí el único atributo propio de cada conjunto es cab, que apunta al primer nodo. Cada nodo lleva al siguiente y el último tiene la liga en null.

cab --> [10 | *] --> [20 | *] --> [30 | null]

Casi todos los métodos usan este recorrido:

Nodo actual = cab;
while (actual != null) {
  // se usa actual.getDato()
  actual = actual.getLiga();
}

Para borrar se llevan dos referencias, anterior y actual. Si el elemento está en la cabeza, cab pasa al segundo nodo; en otro caso, el anterior se enlaza con el que sigue.

Antes de borrar el 20     [10] --> [20] --> [30]
Después                   [10] -----------> [30]

6. Conjunto universal

El universal se define primero y no se forma a partir de los demás. Es al contrario: A y B se construyen con elementos que ya están en él. Si se redefine, el programa vuelve a pedir A y B, porque podrían contener datos que ya no son válidos.

Se guarda como atributo static, pues es uno solo y lo comparten todos los conjuntos de la clase. Así complemento no necesita recibirlo. Además se guarda una copia, para que un cambio en el conjunto original no lo altere.

7. Operaciones

OperaciónCómo se obtiene
UniónSe copia A y se agregan los elementos de B; los repetidos se ignoran.
IntersecciónSe toman los elementos de A que pertenecen a B.
DiferenciaSe toman los elementos de A que no pertenecen a B.
Diferencia simétricaSe unen A - B y B - A.
ComplementoSe calcula la diferencia entre el universal y A.
PertenenciaSe busca el elemento y se revisa si tiene posición.
SubconjuntoSe verifica que todos los elementos de A estén en B.
IgualdadTienen la misma cantidad y A es subconjunto de B.
DisjuntosSe verifica que la intersección esté vacía.

Las cinco primeras devuelven un conjunto nuevo y no modifican los originales. Las demás responden verdadero o falso. La igualdad no necesita revisar el otro sentido: como no hay repetidos, si tienen la misma cantidad y todo A está en B, a B no le sobra nada.

Varias operaciones se construyen con las anteriores. La diferencia simétrica es un buen ejemplo:

return diferencia(b).union(b.diferencia(this));

8. Validaciones

  • No se agregan elementos repetidos ni que estén fuera del universal.
  • El universal no puede quedar vacío; A y B sí.
  • Las opciones inválidas y los datos de otro tipo se vuelven a pedir.
  • Los elementos se comparan con equals, por su contenido. En los textos se distinguen mayúsculas.
  • El vector avisa si está lleno. En el menú, A y B tienen capacidad para todo el universal, así que no se desbordan.

10. Conclusiones

Un mismo conjunto se puede guardar de formas distintas sin que cambien sus operaciones. La unión da igual en el vector y en la lista; lo que cambia es la manera de recorrer los elementos para llegar a ella.

Cada representación tiene lo suyo. El vector es directo, pero hay que darle un tamaño desde el principio y mover elementos al borrar. La lista crece según se necesite, aunque para llegar a un elemento toca pasar por los anteriores.

La pertenencia resultó ser la base de casi todo. Con ella se resuelven la intersección, la diferencia y el subconjunto, y al combinarlas salen las demás sin repetir lógica.

También queda claro por qué el universal va primero: sin él no hay contra qué calcular el complemento ni cómo saber qué elementos son válidos.
